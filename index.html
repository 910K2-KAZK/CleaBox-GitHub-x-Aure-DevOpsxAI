Project Clearbox — Integration Vision
Project Clearbox / プロジェクト・クリアボックス

GitHub × Azure DevOps × AI 統合アーキテクチャ — ゼロ・ブラックボックス構想

A proposed integration layer connecting GitHub (source of truth), Azure DevOps (CI/CD), and an AI intelligence layer — enabling full traceability, automated progress reporting with defined denominators, and cross-platform knowledge transparency. GitHub（信頼できる唯一の情報源）、Azure DevOps（CI/CD）、AIインテリジェンスレイヤーを統合し、完全なトレーサビリティ・分母定義済みの進捗報告・クロスプラットフォームの知識透明化を実現する提案です。

Architecture overview アーキテクチャ概要
Layer breakdown — click to expand レイヤー詳細 — クリックして展開
GitHub — Single source of truth GitHub — 唯一の信頼できる情報源
All code, documentation, RCA logs, and KT materials live here. Non-negotiable baseline. コード・ドキュメント・RCAログ・KT資料のすべてがここに集約される。交渉の余地のない基準線。
LAYER 1
Code repositoryコードリポジトリ
Feature branches, PRs, commit history. All changes traceable.フィーチャーブランチ、PR、コミット履歴。すべての変更が追跡可能。
/docs folder/docsフォルダ
Specs, RCA logs, KT documents. Searchable by AI. Not in email.仕様書・RCAログ・KT資料。AIで検索可能。メールに置かない。
Issues & ProjectsIssuesとProjects
Task tracking with defined scope (denominator). Progress = closed issues / total.スコープ定義済みのタスク管理（分母）。進捗 = 完了Issue / 総数。
Actions workflowActionsワークフロー
Lint, unit test, build on every PR. Triggers Azure Pipeline on merge.PR毎にlint・ユニットテスト・ビルド。マージ時にAzure Pipelineをトリガー。
Azure DevOps — CI/CD & delivery Azure DevOps — CI/CDと本番デリバリー
Integration tests, staging deployment, approval gates, production release. Complements GitHub, not replaces it. 統合テスト・ステージングデプロイ・承認ゲート・本番リリース。GitHubを置き換えるのではなく補完する。
LAYER 2
Pipelinesパイプライン
Triggered by GitHub webhook. Integration test → staging → prod.GitHubのwebhookでトリガー。統合テスト → ステージング → 本番。
Approval gate承認ゲート
Manual sign-off before production. Accountable owner recorded.本番前の手動承認。責任者が記録される。
Status write-backステータス書き戻し
Pipeline result posted back to GitHub commit/PR. Visible in one place.パイプライン結果をGitHubのコミット/PRに書き戻す。一か所で確認。
Monitorモニタリング
Metrics and alerts. Failures auto-create GitHub Issues via webhook.メトリクスとアラート。障害はwebhook経由でGitHub Issueを自動作成。
AI layer — Intelligence & transparency AIレイヤー — インテリジェンスと透明化
Reads both GitHub and Azure DevOps. Synthesizes RCA logs, checks progress denominators, auto-generates KT documents. GitHub・Azure DevOps双方を読み取る。RCAログを統合し、進捗の分母を確認し、KT資料を自動生成する。
LAYER 3
Code analysisコード解析
PR review assistance, anomaly detection in commit patterns.PRレビュー支援、コミットパターンの異常検知。
KT retrievalKT検索・生成
Searches /docs, RCA logs, commit messages. Answers "what did we decide about X."/docs・RCAログ・コミットメッセージを横断検索。「Xについて何を決めたか」に答える。
Progress report進捗レポート
Denominator-aware summary: "3 of 8 modules done, target 2026-06-20."分母定義済みのサマリー：「8モジュール中3完了、目標2026-06-20」
Alert triageアラートトリアージ
Correlates Monitor alerts with commit history. Root cause candidate in seconds.Monitorアラートとコミット履歴を照合。数秒で根本原因の候補を提示。
Integration flow — PR to production 統合フロー — PRから本番まで
1
Developer opens PR on GitHub開発者がGitHubでPRを作成
GitHub Actions immediately runs lint and unit tests. AI layer reviews the diff and posts comments.GitHub Actionsがlintとユニットテストを即時実行。AIレイヤーがdiffをレビューしコメントを投稿。
2
PR merge triggers Azure PipelinePRマージがAzure Pipelineをトリガー
GitHub Actions calls Azure DevOps REST API via webhook. Pipeline takes over: integration test → staging deploy.GitHub ActionsがwebhookでAzure DevOps REST APIを呼び出す。パイプラインが引き継ぎ：統合テスト → ステージングデプロイ。
POST https://dev.azure.com/{org}/{project}/_apis/build/builds
Authorization: Bearer {PAT}
Body: { "definition": { "id": {pipeline_id} } }
3
Approval gate — accountable owner signs off承認ゲート — 責任者が承認
Prod deploy requires explicit approval. Who approved, when, and what build — all recorded in Azure Boards and written back to GitHub.本番デプロイには明示的な承認が必要。誰が・いつ・何のビルドを承認したか — すべてAzure Boardsに記録されGitHubに書き戻される。
4
Pipeline result written back to GitHub commitパイプライン結果をGitHubコミットに書き戻し
Pass or fail is visible directly in the PR thread. One place to check. No hunting across two platforms.合否がPRスレッドに直接表示される。確認は一か所。二つのプラットフォームを行き来しない。
POST /repos/{owner}/{repo}/statuses/{sha}
{ "state": "success", "context": "azure-pipelines/prod" }
5
AI layer generates weekly progress reportAIレイヤーが週次進捗レポートを自動生成
Reads closed Issues vs total Issues, pipeline pass rate, open alerts. Output: denominator-defined status — not "30% completed."完了Issue数 / 総Issue数、パイプライン合格率、未解決アラートを読み取る。出力：分母定義済みのステータス — 「30%完了」ではなく。
Completed: 3 of 8 modules (DB schema, API layer, deployment runbook remaining)
Pipeline pass rate (last 14d): 94%
Target: 2026-06-20 (confirmed)
↻
Alert failures auto-create GitHub Issuesアラート障害がGitHub Issueを自動作成
Azure Monitor alert → webhook → GitHub Issue with RCA template, assigned owner, and target resolution date. Nothing falls through the gap.Azure Monitorアラート → webhook → RCAテンプレート付きGitHub Issue、担当者と解決目標日時を自動設定。抜け漏れゼロ。
